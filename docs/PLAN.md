# VideoDetection — план проекту

**Мета:** детекція людей і аналіз їх поведінки на відео з ESP32-S3 CAM.
**Головна ціль — навчальна:** освоїти ESP32CAM, стрімінг, OpenCV, YOLO, повний ML-цикл.

## Архітектура

```
ESP32-S3 CAM ──MJPEG/WiFi──> ХАБ ──> YOLO detect + pose ──> трекінг ──> правила поведінки
   "око"                   (ноут/RPi5)                                        │
                                                                    веб-UI + події
                                                              (браузер, смартфон, Telegram)
```

YOLO **не** крутиться на ESP32 — у неї ~8 МБ PSRAM і векторні інструкції, чого
вистачає лише на крихітні ESP-DL моделі. ESP32 = камера + Wi-Fi транспорт.

**Хаб:** ноут (Core Ultra 7 155H, iGPU Arc + NPU) для розробки й навчання,
RPi 5 8GB для фінального цілодобового деплою.

### Етап 0 — Каркас ✅
Структура репо, git, PlatformIO-проект, venv, requirements.

### Етап 1 — Камера стрімить 🔄
Прошивка `firmware/esp32s3_cam`: MJPEG на `:81/stream`, `/status` з телеметрією,
`/control` для зміни режимів на льоту, статичний IP, mDNS, авто-reconnect.

**Що виміряти:** FPS і розмір кадру для QVGA / VGA / SVGA / HD × quality 8/12/16.
Результат — таблиця, з якої обираємо робочий режим.

### Етап 2 — Приймач на Python
Клієнт MJPEG, стійкий до розривів. Ключова ідея: **читати в окремому потоці й
викидати старі кадри**, інакше затримка накопичується — OpenCV віддає кадри
з черги, а не найсвіжіший.

Освоюємо: `cv2.VideoCapture`, BGR/RGB, ресайз, `cv2.imshow`, запис відео,
авто-семплінг кадрів у `captures/` для майбутнього датасету.

### Етап 3 — Перша детекція
YOLO11n pretrained на COCO, фільтр по класу `person`.
Розбираємо: що таке confidence, IoU, NMS, чому `imgsz` важливий.
Бенчмарк CPU vs OpenVINO iGPU vs NPU — таблиця FPS.

### Етап 4 — Стрім результату
FastAPI на хабі: приймає з ESP32, малює боксy, віддає анотований MJPEG
+ адаптивна веб-сторінка для телефона. Пізніше — WebRTC (MediaMTX) для затримки.

### Етап 5 — Трекінг і поведінка
- ByteTrack — стабільні ID замість миготіння боксів
- YOLO11n-**pose** — 17 ключових точок скелета
- геометричні правила: зони, перетин лінії з напрямком, dwell time
- детекція падіння: орієнтація bbox + висота центру мас скелета
- машина станів на трек з дебаунсом, щоб не сипало хибними алармами
- події → MQTT / Telegram, збереження кліпів

### Етап 6 — Датасет і навчання
Два рівні, і це **два різні тренування**:

*Рівень 1 — детектор під свою камеру.* 500–2000 кадрів з власної ESP32
(шум OV2640, ракурс, нічне світло, дрібні фігури). Розмітка в CVAT/Label Studio,
auto-labeling великою YOLO11x з ручною правкою. Fine-tune YOLO11n,
читання метрик: precision/recall, mAP50, mAP50-95, confusion matrix.
Порівняння baseline vs fine-tuned на власному test-сеті.

*Рівень 2 — класифікатор дій.* Поведінку не розмічають боксами. Датасет —
**послідовності**: вікна по N кадрів з pose-координатами. Модель — LSTM/GRU
або градієнтний бустинг по фічах скелета, поверх YOLO-pose. Класи на кшталт
стоїть / йде / біжить / сидить / впав.

### Етап 7 — Деплой на RPi 5
Експорт у NCNN/ONNX, INT8-квантизація, бенчмарк, systemd-сервіс, автозапуск.
Реалістично: YOLO11n-pose @320 NCNN INT8 ≈ 10–15 FPS — для поведінкової
аналітики достатньо. Опційно Hailo-8L AI Kit (~$70) для ~30+ FPS.

### Етап 8 — Опції
ESP-DL детекція руху на самій ESP32 як wake-on-motion (щоб не стрімити 24/7),
VLM через локальну Ollama для текстових описів подій, кілька камер.

## Орієнтири по часу
- працюючий детектор з веб-переглядом — ~1 тиждень вечорами
- повний цикл з власною моделлю на RPi5 — ~4–6 тижнів

## Граблі заліза
- **живлення:** стабільні 5V / ≥1A, інакше випадкові ребути під навантаженням
- **перегрів** модуля при тривалому HD-стрімі 24/7
- **Wi-Fi тільки 2.4 ГГц**, MJPEG їсть ~1–3 Мбіт/с на камеру
